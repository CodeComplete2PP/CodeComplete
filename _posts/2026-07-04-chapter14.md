## 14장: 순차적 코드 구성하기

### 14.1 특정 순서로 배치해야 하는 명령문

- 순서 의존성이 있는 코드는 의존 관계가 분명하게 보이도록 배치함
- 한 명령문의 결과를 다음 명령문이 사용한다면 두 문장을 가깝게 두고 데이터 흐름을 위에서 아래로 만듦
- 매개변수나 객체 상태를 먼저 설정해야 하는 호출은 초기화와 사용 사이에 다른 코드를 끼워 넣지 않음
- 순서가 중요하지만 코드만으로 드러나지 않으면 이름, 루틴 분리, 주석으로 제약을 명시함
- 순서 의존성을 줄일 수 있다면 루틴에 필요한 데이터를 명시적으로 전달하거나 객체가 유효한 상태를 스스로 유지하게 함

#### 명령문 순서를 정하는 지침

- 호출 전에 사용하는 값을 준비함
- 관련된 작업은 한 덩어리로 모음
- 오류 처리나 정리 작업은 정상 처리 흐름을 방해하지 않게 배치함
- 코드가 실행 순서뿐 아니라 논리적 사고 순서도 보여 주게 함

### 14.2 순서가 중요하지 않은 명령문

- 순서 제약이 없다면 가독성을 높이는 순서를 선택함
- 서로 관련된 명령문을 함께 두어 코드를 훑을 때 한 주제를 한 번에 파악하게 함
- 코드를 위에서 아래로 읽을 때 호출되는 루틴이나 처리 단계가 자연스럽게 이어지도록 구성함
- 변수의 참조 범위가 짧아지도록 선언, 계산, 사용을 가까이 둠
- 명령문 사이에 빈 줄을 사용해 문단을 만들고 각 문단이 하나의 작업을 나타내게 함
- 임의의 알파벳순이나 기계적인 정렬보다 프로그램의 논리를 설명하는 순서를 우선함

### 참고 자료

- 순차적 코드 구성은 루틴 응집도, 변수 범위, 제어 구조의 복잡성과 함께 검토해야 함

### 요점 정리

- 순서 의존성이 필요한 코드에서는 의존 관계가 눈에 보이도록 명령문을 배치해야 한다.
- 순서가 중요하지 않다면 관련성, 가독성, 변수의 짧은 사용 범위를 기준으로 순서를 정한다.
- 명령문을 논리적 문단으로 묶으면 순차적 코드의 구조와 의도가 선명해진다.
