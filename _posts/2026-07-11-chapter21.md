## 21장: 협력 구현

### 21.1 협력 개발 기법 개요

- 협력 구현은 다른 개발자의 관점으로 설계와 코드의 결함을 조기에 찾는 활동임
- 협력은 코드 품질뿐 아니라 지식 공유, 표준 확산, 공동 소유권을 높임
- 검토의 목표는 작성자를 평가하는 것이 아니라 산출물을 개선하는 것임

### 21.2 페어 프로그래밍

- 두 사람이 한 컴퓨터에서 운전자와 관찰자 역할을 나누고 지속적으로 코드를 검토함
- 두 역할을 주기적으로 바꾸며 한 사람은 구현 세부사항, 다른 사람은 방향과 결함을 살핌
- 코드 표준을 지키고, 서로 다른 경험의 짝을 구성하고, 코드 소유권을 공유할 때 효과가 큼
- 혼자 할 때보다 인력 비용이 늘 수 있지만 결함 감소, 재작업 감소, 교육 효과로 상쇄될 수 있음
- 성격 충돌, 일방적 지시, 피로를 줄이도록 휴식과 역할 교대를 관리함

### 21.3 공식 검사

- 검사에는 작성자, 진행자, 검토자, 기록자처럼 명확한 역할을 둠
- 개요 설명, 개별 준비, 검사 회의, 수정, 후속 확인의 단계를 따름
- 회의에서는 해결책 토론보다 결함 발견과 기록에 집중함
- 검토 속도와 산출물 크기를 제한하고 참가자가 사전에 개별 검토하게 함
- 결함 자료를 익명화해 프로세스 개선에 사용하고 개인 평가에는 사용하지 않음

### 21.4 다른 협력 개발 기법

- 워크스루는 작성자가 코드를 설명하며 동료의 질문과 의견을 받는 비교적 비공식적인 방법임
- 코드 읽기, 데스크 체킹, 동료 검토는 공식 검사보다 가볍게 적용할 수 있음
- 작업 위험과 팀 상황에 맞게 형식 수준을 정하되 준비와 후속 수정을 생략하지 않음

### 요점 정리

- 다른 개발자의 관점은 혼자 놓치기 쉬운 결함과 설계 문제를 조기에 드러낸다.
- 협력 기법은 형식보다 준비와 결함을 실제로 수정하는 후속 조치가 중요하다.

### 참고 자료

- 공식 검사와 페어 프로그래밍에 관한 경험 연구는 적용 비용과 결함 제거 효과를 비교하는 자료를 제공함
