## 9장: 의사코드 프로그래밍 프로세스

### 9.1 클래스 및 루틴 개발 단계 요약

- 문제를 정의하고 요구사항과 선행 조건을 확인함
- 인터페이스, 책임, 데이터, 오류 조건을 먼저 설계함
- 의사코드로 알고리즘을 작성하고 검토한 뒤 실제 코드로 옮김
- 구현 후에는 각 루틴을 독립적으로 검토하고 테스트함

### 9.2 전문가를 위한 의사코드

- 의사코드는 자연어와 코드 사이의 중간 설계 언어임
- 특정 언어의 문법에 묶이지 않으면서 제어 흐름과 의도를 표현함
- 한 문장은 실제 코드 한 줄보다 높은 수준의 작업 하나를 나타내야 함
- 좋은 의사코드는 구현 전에 논리 오류를 드러내고 리뷰를 쉽게 함

### 9.3 PPP를 이용한 루틴 구현

- 루틴의 목적과 사전·사후 조건을 적음
- 최상위 작업을 의사코드로 작성하고, 각 작업을 계속 세분화함
- 의사코드가 충분히 구체화되면 코드로 변환함
- 코드로 옮긴 뒤에는 의사코드와 실제 구현의 차이를 점검함

### 9.4 PPP 대안

- 테스트 주도 개발, 설계 우선 방식, 리팩터링 중심 방식도 사용할 수 있음
- 어떤 프로세스를 선택하든 설계·구현·검토·테스트의 책임을 생략하지 않음

### 참고 자료

- 이 장에는 별도 참고 자료 목록이 없음

### 요점 정리

- 의사코드 프로그래밍 프로세스는 설계와 코딩을 분리해 루틴의 논리를 먼저 명확히 한다.
- 의사코드는 문법보다 의도와 작업 수준을 표현해야 한다.
- PPP는 유일한 방법이 아니며 프로젝트와 팀에 맞는 프로세스를 선택할 수 있다.
