## 22장: 개발자 테스트

### 22.1 소프트웨어 품질에서 개발자 테스트의 역할

- 개발자 테스트에는 단위 테스트와 구성 요소 통합 테스트가 포함됨
- 테스트의 목적은 코드가 동작함을 증명하는 것보다 결함을 찾는 데 있음
- 개발자는 자신의 가정에 익숙하므로 독립 테스트와 검토를 대체할 수 없음
- 테스트 용이성을 고려한 설계는 인터페이스, 결합도, 관찰 가능성도 개선함

### 22.2 권장하는 개발자 테스트 접근

- 각 요구사항과 설계 결정에 대응하는 테스트를 작성함
- 구현 전에 테스트 사례를 생각해 인터페이스와 오류 조건을 분명히 함
- 새 코드와 수정한 코드는 자동 회귀 테스트에 추가함
- 정상 사례뿐 아니라 잘못된 입력과 실패 경로를 같은 비중으로 확인함

### 22.3 테스트 기법 모음

- 불완전하거나 모순된 요구사항을 찾기 위해 명세를 기준으로 테스트함
- 모든 명령문과 분기를 실행하는 구조 기반 테스트로 빠진 경로를 찾음
- 경계값, 최소값, 최대값, 0, 빈 컬렉션, 한 요소를 집중적으로 확인함
- 유효한 데이터와 유효하지 않은 데이터를 동등 분할해 대표값을 고름
- 흔히 틀리는 오류를 추정하고 이미 발견된 결함 주변에 추가 테스트를 만듦
- 무작위 입력과 독립적인 결과 계산 수단으로 넓은 입력 공간을 탐색함

### 22.4 전형적인 오류

- 오류는 일부 루틴과 모듈에 집중되는 경향이 있으므로 결함이 발견된 영역을 더 깊이 검사함
- 제어 흐름, 데이터 초기화, 인터페이스, 계산, 경계 처리 오류를 체계적으로 분류함
- 수정 자체가 새 결함을 만들 수 있으므로 수정 전후의 관련 동작을 다시 테스트함

### 22.5 테스트 지원 도구

- 테스트 프레임워크, 비교 도구, 커버리지 도구, 메모리 검사기, 데이터 생성기를 활용함
- 테스트용 스텁과 드라이버로 아직 완성되지 않은 구성 요소를 격리함
- 테스트 코드도 제품 코드처럼 읽기 쉽고 신뢰할 수 있게 유지함

### 22.6 테스트 개선

- 결함 발견률과 커버리지를 측정해 테스트가 약한 영역을 찾음
- 테스트 결과를 검토하고 같은 종류의 결함을 더 빨리 찾는 방법을 개선함

### 22.7 테스트 기록 유지

- 실행한 테스트, 결과, 발견한 결함, 수정 상태를 기록함
- 테스트 기록으로 신뢰성이 높아지는 추세와 남은 위험을 판단함

### 요점 정리

- 좋은 개발자 테스트는 코드가 잘 동작한다는 증명보다 결함을 찾는 데 초점을 둔다.
- 경계값과 실패 경로를 포함한 작고 자동화된 테스트가 회귀를 막는 기반이 된다.

### 참고 자료

- 단위 테스트, 구조 기반 테스트, 테스트 커버리지 자료를 함께 참고하면 개발자 테스트 기법을 확장할 수 있음
