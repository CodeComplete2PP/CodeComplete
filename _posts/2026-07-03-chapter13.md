## 13장: 특이한 데이터형

### 13.1 구조체

- 서로 관련된 데이터를 하나의 의미 있는 단위로 묶음
- 구조체가 단순 묶음인지 책임을 가진 추상화인지 구분함

### 13.2 포인터

- 포인터는 주소와 간접 참조를 표현하며 강력하지만 오류 가능성이 큼
- 초기화, 수명, 소유권, 널 포인터, 해제 책임을 명확히 함
- 포인터 연산은 한곳에 격리하고 직접 조작을 최소화함

### 13.3 전역 데이터

- 전역 데이터는 모든 코드가 의존할 수 있어 결합도와 변경 위험을 높임
- 꼭 필요하다면 접근 루틴과 변경 지점을 제한함

### 13.4 데이터형의 비정상적인 사용

- 서로 다른 의미의 값을 문자열·정수 하나로 표현하면 오류가 늦게 드러남
- 플래그 비트, 상태 코드, 타입 변환은 이름 있는 추상화로 감쌈

### 13.5 자료구조 선택

- 자료구조는 데이터의 크기, 접근 패턴, 삽입·삭제 빈도, 정렬 필요성으로 선택함
- 성능보다 먼저 자료구조가 문제 도메인을 올바르게 표현하는지 확인함

### 13.6 사용자 정의 타입

- 도메인 값의 유효 범위와 연산을 타입 안에 모음
- 타입을 새로 만드는 비용보다 잘못된 값이 시스템에 퍼지는 비용이 큰지 비교함

### 참고 자료

- 이 장에는 별도 참고 자료 목록이 없음

### 요점 정리

- 특이한 데이터형은 표현력이 큰 만큼 수명, 소유권, 공유 상태를 명확히 해야 한다.
- 자료구조와 사용자 정의 타입은 구현 편의보다 데이터의 의미와 사용 방식을 기준으로 선택한다.
