## 26장: 코드 튜닝 기법

### 26.1 논리

- 답을 알게 되는 즉시 평가를 끝내도록 조건 순서와 단락 평가를 활용함
- 여러 조건을 매번 평가하기보다 빈도가 높은 사례를 먼저 처리하거나 테이블로 바꿈
- 복잡한 논리를 단순한 수학식이나 미리 계산한 결과로 대체할 수 있는지 검토함

### 26.2 반복문

- 반복문 안에서 변하지 않는 계산과 루틴 호출을 밖으로 이동함
- 반복 횟수를 줄이고 가능하면 여러 반복을 결합하되 가독성과 캐시 효과를 측정함
- 가장 안쪽 반복문의 작업량을 줄이고, 종료 조건과 인덱스 계산 비용을 확인함
- sentinel 값을 사용해 매 반복의 경계 검사를 줄이는 기법은 안전성이 보장될 때만 사용함

### 26.3 데이터 변환

- 실행 중 반복 계산하는 값을 초기화 시점에 미리 계산함
- 계산하기 쉬운 형태로 데이터를 바꾸거나 보조 인덱스를 두어 조회 비용을 줄임
- 메모리 사용 증가와 실행 시간 감소의 절충을 측정함

### 26.4 표현식

- 비용이 큰 연산을 더 싼 동등 연산으로 바꾸되 현대 컴파일러가 이미 수행하는지 확인함
- 공통 부분식을 한 번만 계산하고 불필요한 형 변환과 임시 객체를 줄임
- 정수와 부동소수점 연산을 선택할 때 정확성, 범위, 실제 실행 비용을 함께 검토함
- 대수적 변환은 overflow와 반올림 결과를 바꿀 수 있으므로 테스트함

### 26.5 루틴

- 매우 작고 자주 호출되는 루틴만 인라인 후보로 검토함
- 추상화를 없애기 전에 호출 비용이 실제 병목인지 측정함

### 26.6 저수준 언어로 다시 작성하기

- 어셈블리 같은 저수준 구현은 이식성과 유지보수성을 크게 낮추므로 최후의 수단으로 둠
- 대체할 코드를 작게 격리하고 고수준 기준 구현과 성능·정확성을 비교함

### 26.7 변할수록 그대로인 원칙

- 구체적인 최적화 효과는 언어, 컴파일러, 프로세서가 바뀌면 달라짐
- 측정하고 병목에 집중하며 변경 후 다시 검증하는 원칙은 환경이 바뀌어도 유지됨

### 요점 정리

- 튜닝 기법은 논리, 반복문, 자료, 표현식, 루틴의 비용을 줄이는 방향으로 적용한다.
- 저수준 최적화보다 알고리즘과 데이터 접근을 먼저 검토하고, 모든 변경을 측정으로 확인한다.

### 참고 자료

- 플랫폼별 최적화 자료는 후보 기법을 제시할 뿐이며 실제 적용 여부는 측정으로 결정해야 함
