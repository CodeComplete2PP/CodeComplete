## 31장: 레이아웃과 스타일

### 31.1 레이아웃의 기본 원칙

- 레이아웃의 주된 목적은 코드의 논리적 구조를 정확하게 보여 주는 것임
- 보기 좋은 장식보다 읽기 쉬움, 일관성, 수정 안전성을 우선함
- 사람이 수동으로 맞추기 어려운 규칙은 자동 포맷터로 일관되게 적용함

### 31.2 레이아웃 기법

- 공백, 들여쓰기, 괄호, 빈 줄을 사용해 관련 코드를 묶고 서로 다른 작업을 분리함
- 한 줄에 너무 많은 내용을 넣지 않고 긴 표현식은 논리적 경계에서 나눔
- 정렬은 관계를 보여 줄 때만 사용하고 작은 수정 때문에 전체 정렬이 깨지는 형식은 피함

### 31.3 레이아웃 스타일

- 순수 블록, 괄호 위치, 들여쓰기 방식에는 여러 합리적인 선택이 있음
- 어느 스타일이든 코드 구조를 숨기지 않고 프로젝트 전체에서 일관돼야 함
- 개인 취향보다 팀 표준과 기존 코드의 일관성을 우선함

### 31.4 제어 구조 배치

- 조건과 반복문의 본문을 일관되게 들여쓰고 시작과 끝을 쉽게 찾게 함
- 깊은 중첩은 레이아웃으로 감추지 말고 제어 구조 자체를 단순화함
- 여러 줄 조건은 연산자와 하위 조건의 관계가 보이게 배치함

### 31.5 개별 명령문 배치

- 한 줄에는 한 명령문을 두고 데이터 선언은 사용 위치 가까이에 둠
- 복잡한 대입과 표현식은 중간값에 이름을 붙여 여러 줄로 나눔
- 연속 줄 정렬이 논리적 관계를 드러내지 않으면 일반적인 들여쓰기를 사용함

### 31.6 주석 배치

- 주석을 설명하는 코드 가까이에 두고 코드와 시각적으로 구분함
- 줄 끝 주석의 긴 열 맞춤은 유지보수 비용이 크므로 제한함

### 31.7 루틴 배치

- 루틴 이름, 매개변수, 본문, 종료 경계를 빠르게 파악할 수 있게 함
- 긴 매개변수 목록은 의미 단위로 줄을 나누고 일관된 들여쓰기를 사용함

### 31.8 클래스 배치

- 클래스 인터페이스를 먼저 보여 주고 구현 세부사항은 분리함
- 관련 데이터와 루틴을 함께 두고 공개 범위나 책임에 따라 순서를 정함

### 요점 정리

- 좋은 레이아웃은 코드를 장식하는 것이 아니라 구조를 빠르게 파악하게 한다.
- 스타일 규칙은 팀 전체에 적용하고 자동화해 중요한 설계 논의에 집중한다.

### 참고 자료

- 레이아웃 표준은 언어 관례와 팀 도구를 반영하되 논리 구조를 보여 준다는 목적을 유지해야 함
