## 10장: 변수 사용 시 고려할 사항

### 10.1 데이터 리터러시

- 변수는 이름, 타입, 수명, 범위, 값, 용도를 함께 가진다.
- 변수의 역할을 명확히 하면 코드를 읽고 변경하기 쉬워짐

### 10.2 변수 선언을 쉽게 만들기

- 변수를 사용하는 위치와 가까운 곳에서 선언함
- 한 선언문에 여러 변수를 묶지 않고 의미 있는 타입을 사용함
- 선언부만 읽어도 변수의 목적과 초기 상태를 알 수 있게 함

### 10.3 변수 초기화 지침

- 변수를 선언할 때 초기화하고, 유효하지 않은 상태를 표현하지 않음
- 초기화 누락, 잘못된 재초기화, 이전 반복의 값 재사용을 주의함
- 입력값과 계산 결과를 구분하고, 모든 경로에서 값이 정해지는지 확인함

### 10.4 범위

- 범위가 넓을수록 값을 추적해야 할 코드가 늘어남
- 지역 변수와 작은 범위를 우선하고 전역 변수는 최소화함

### 10.5 지속성

- 변수의 수명이 길수록 상태 변화와 초기화 순서를 이해하기 어려워짐
- 필요한 동안만 유지하고, 오래 사는 상태는 명시적인 객체나 저장소로 관리함

### 10.6 바인딩 시점

- 타입·값·주소를 언제 결정할지 선택하면 유연성과 복잡성의 균형이 달라짐
- 늦은 바인딩은 유연하지만 추적과 검증 비용을 높일 수 있음

### 10.7 데이터 타입과 제어 구조의 관계

- 데이터 타입을 잘 선택하면 조건문과 변환 코드가 줄어듦
- 상태를 표현하는 타입과 제어 구조가 서로 자연스럽게 대응되는지 확인함

### 10.8 변수 하나를 한 가지 목적으로만 사용

- 한 변수에 여러 의미를 재사용하면 코드 이해와 디버깅이 어려워짐
- 루프 카운터, 임시값, 반환값을 분리해 각 변수의 책임을 좁힘

### 참고 자료

- 이 장에는 별도 참고 자료 목록이 없음

### 요점 정리

- 좋은 변수는 명확한 이름과 타입, 좁은 범위, 짧은 수명, 분명한 초기화를 가진다.
- 변수 하나를 여러 목적으로 재사용하지 않으면 데이터 흐름과 오류 원인을 추적하기 쉬워진다.
