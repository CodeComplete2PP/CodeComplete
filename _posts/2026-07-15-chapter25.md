## 25장: 코드 튜닝 전략

### 25.1 성능 개요

- 성능에는 실행 속도뿐 아니라 메모리, 디스크, 네트워크 사용량, 시작 시간 등이 포함됨
- 요구사항, 설계, 클래스와 루틴, 운영체제 상호작용에서 얻는 개선이 코드 수준 조정보다 큰 경우가 많음
- 성능 목표를 수치로 정의하고 정확성, 가독성, 유지보수성과의 우선순위를 정함

### 25.2 코드 튜닝 소개

- 코드 튜닝은 정확한 코드에서 측정된 병목을 개선하는 마지막 단계의 활동임
- 컴파일러와 하드웨어의 동작을 추측해 미리 최적화하지 않음
- 작은 최적화는 이해하기 어려운 코드를 만들 수 있으므로 효과가 입증된 부분에만 적용함

### 25.3 느리고 비대한 코드의 종류

- 입력과 함께 급격히 늘어나는 비효율적 알고리즘을 먼저 확인함
- 불필요한 입출력, 시스템 호출, 메모리 할당, 형 변환, 루틴 호출을 찾음
- 성능 문제는 코드의 작은 일부에 집중되는 경향이 있으므로 전체 코드를 손대지 않음
- 특정 언어 구성의 비용은 환경과 컴파일러에 따라 달라지므로 일반화하지 않음

### 25.4 측정

- 프로파일러로 실제 실행 시간과 호출 빈도를 측정해 병목을 찾음
- 대표적인 데이터와 실제와 가까운 환경에서 기준 성능을 기록함
- 변경 전후를 같은 조건에서 비교하고 정확성 회귀도 함께 검사함

### 25.5 반복

- 한 번에 한 가지 최적화를 적용하고 측정 결과가 나쁘면 되돌림
- 여러 작은 개선의 효과는 단순히 합산되지 않을 수 있으므로 전체 성능을 다시 측정함

### 25.6 코드 튜닝 접근 요약

- 동작하는 코드를 개발하고, 성능을 측정하고, 병목을 찾고, 한 부분을 개선하고, 다시 측정함
- 목표에 도달하면 더 이상 튜닝하지 않고 유지보수 가능한 상태를 보존함

### 요점 정리

- 코드 튜닝은 측정으로 병목을 확인하고 가장 큰 효과가 예상되는 곳부터 진행한다.
- 최적화 전후의 정확성과 성능을 모두 검증하지 않으면 개선이 아니라 위험이 된다.

### 참고 자료

- 성능 측정과 알고리즘 분석 자료는 코드 튜닝 전에 병목의 수준을 판단하는 데 도움을 줌
