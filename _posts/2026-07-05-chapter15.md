## 15장: 조건문 사용

### 15.1 `if` 문

#### 단순한 `if-then` 문

- 먼저 정상 경로를 작성하고 조건이 참일 때 실제로 필요한 동작만 넣음
- 동등 비교를 실수로 대입으로 쓰지 않도록 언어의 컴파일러 경고와 명확한 표현을 활용함
- 정상적인 경우에는 블록이 수행되고 오류나 드문 경우에는 건너뛰는 형태가 읽기 쉬움
- 빈 블록은 피하고, 의도적으로 아무 일도 하지 않는다면 이유를 명시함

#### `if-then-else` 문

- 정상적이고 흔한 경우를 먼저 두고 드문 경우를 `else`에 배치함
- 두 분기의 처리량과 중요도를 비교해 주 흐름이 잘 보이게 함
- 조건은 가능하면 긍정형으로 쓰고, 부정 조건과 부정 동작이 겹치지 않게 함
- `else` 절이 올바른 `if`에 연결되는지 중첩과 들여쓰기를 확인함
- 연속된 조건이 같은 변수를 분류한다면 독립된 `if`보다 `else if` 사슬을 사용함

#### 중첩된 조건문

- 중첩이 깊어지면 조건 일부를 별도 루틴이나 boolean 변수로 옮김
- 경비 절과 조기 반환으로 예외 조건을 먼저 제거해 정상 경로의 들여쓰기를 줄임
- 조건을 뒤집거나 분기 코드를 재배치해 주 흐름을 왼쪽에 유지함
- 여러 수준의 조건이 서로 다른 책임을 다룬다면 루틴을 분리함

### 15.2 `case` 문

- 하나의 값을 여러 경우로 나눌 때 긴 `if-else` 사슬보다 `case` 문이 의도를 잘 드러냄
- 분기는 의미 있는 순서로 배치함
  - 숫자나 문자 순서
  - 정상적인 경우를 먼저 두는 순서
  - 실행 빈도에 따른 순서
- 각 분기의 끝을 명확히 하고 의도하지 않은 fall-through를 막음
- 정상적인 모든 경우를 명시적으로 처리하고, 불가능한 값은 기본 분기에서 오류로 드러냄
- 기본 분기를 단순한 만능 처리로 사용해 빠진 정상 사례를 숨기지 않음
- 분기별 동작이 크거나 계속 늘어나면 각 동작을 루틴으로 분리하거나 다형성 같은 설계를 검토함

### 참고 자료

- 조건문은 boolean 표현식, 깊은 중첩, 제어 구조 복잡성에 관한 19장의 지침과 함께 적용함

>> #### 체크리스트: 조건문
>> **`if-then` 문**
>> - 정상 경로가 명확한가?
>> - 동등 비교와 대입을 혼동할 가능성이 없는가?
>> - 블록 경계가 분명한가?
>>
>> **`if-then-else` 문**
>> - 가장 흔한 경우가 먼저 나오는가?
>> - 조건을 긍정형으로 표현할 수 있는가?
>> - 중첩을 줄이기 위해 경비 절이나 루틴 분리를 사용할 수 있는가?
>>
>> **`case` 문**
>> - 분기 순서에 의미가 있는가?
>> - 모든 정상 값과 예상하지 못한 값을 처리하는가?
>> - 의도하지 않은 fall-through가 없는가?

### 요점 정리

- 조건문은 정상 경로가 가장 잘 보이도록 구성하고, 드문 경우와 오류 처리는 주 흐름에서 분리해야 한다.
- 깊은 중첩은 조건 재구성, 경비 절, 루틴 분리로 줄일 수 있다.
- 여러 선택지 중 하나를 고르는 코드에서는 완전하고 명확한 `case` 문이 긴 조건 사슬보다 낫다.
