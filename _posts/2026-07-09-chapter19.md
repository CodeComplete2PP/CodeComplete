## 19장: 제어와 관련된 일반적인 문제

### 19.1 boolean 표현식

- 복잡한 조건은 이름 있는 boolean 변수나 루틴으로 바꿔 의미를 드러냄
- 비교식은 읽는 순서가 자연스럽게 왼쪽에서 오른쪽으로 이어지게 함
- 긍정형 조건을 우선하고 이중 부정을 피함
- 숫자를 boolean처럼 사용하지 말고 명시적인 비교를 사용함
- 부동소수점 값은 정확한 동등 비교 대신 허용 오차를 기준으로 비교함
- 범위 검사는 경계의 포함 여부가 분명하게 보이도록 작성함
- AND와 OR가 섞이면 괄호로 평가 순서를 명시하고 복잡하면 여러 조건으로 나눔
- 단락 평가의 부작용에 의존하지 않으며, 필요한 경우에만 안전성 검사에 활용함

### 19.2 복합문

- 여러 명령문을 하나의 블록으로 묶을 때 블록 경계를 항상 명확히 표시함
- 한 줄짜리 조건이나 반복 본문도 중괄호를 사용하면 수정 중 생기는 오류를 줄일 수 있음
- 빈 블록이나 블록 끝의 세미콜론처럼 눈에 잘 띄지 않는 실수를 피함

### 19.3 널 문장

- 아무 동작도 하지 않는 문장은 오타인지 의도인지 구분하기 어려움
- 의도적인 널 문장은 별도 줄에 두고 이유를 설명함
- 가능하면 빈 블록, 명시적인 `continue`, 의미 있는 루틴 호출처럼 더 분명한 표현을 사용함

### 19.4 위험할 정도로 깊은 중첩 다루기

- 깊은 중첩은 가능한 실행 경로를 늘리고 코드를 머릿속에서 추적하기 어렵게 함
- 조건 일부를 다시 검사하거나 조건 순서를 바꿔 중첩을 줄임
- 경비 절로 오류와 예외 조건을 먼저 처리함
- 중첩된 코드를 별도 루틴으로 옮겨 추상화 수준을 맞춤
- 긴 `if-else` 사슬은 `case`, 테이블, 다형성으로 바꿀 수 있는지 검토함
- 상태 변수를 남발해 중첩을 평탄화하면 다른 복잡성이 생길 수 있으므로 전체 가독성을 비교함

### 19.5 프로그래밍의 기반: 구조적 프로그래밍

- 구조적 프로그래밍은 순차, 선택, 반복의 제어 구조로 프로그램을 구성함
- 각 제어 구조가 하나의 진입점과 하나의 종료점을 가지면 조합과 이해가 쉬워짐
- 핵심 목표는 특정 문법 준수가 아니라 제어 흐름의 예측 가능성과 복잡성 감소임
- 현대 언어의 예외, 조기 반환 같은 기능도 전체 흐름을 더 명확하게 만드는지 기준으로 판단함

### 19.6 제어 구조와 복잡성

- 제어 흐름의 복잡성은 분기 수와 중첩 깊이에 따라 증가함
- 루틴의 결정 지점 수를 세는 순환 복잡도는 테스트 경로와 유지보수 위험을 가늠하는 지표임
- 복잡도가 높으면 조건을 단순화하고, 중첩을 줄이고, 루틴을 분리함
- 측정값 자체를 목표로 삼기보다 이해하기 어려운 코드를 찾는 신호로 사용함

### 참고 자료

- 구조적 프로그래밍과 순환 복잡도는 제어 흐름의 이해 가능성과 테스트 비용을 평가하는 기반을 제공함

### 요점 정리

- boolean 표현식은 단순하고 긍정적으로 작성하며, 복잡한 조건에는 의미 있는 이름을 붙여야 한다.
- 깊은 중첩은 코드 이해와 테스트를 어렵게 하므로 조건 재구성, 경비 절, 루틴 분리로 줄인다.
- 구조적 프로그래밍의 핵심은 제어 흐름을 예측 가능하게 만들어 복잡성을 관리하는 것이다.
- 복잡도 측정은 품질 그 자체가 아니라 검토와 개선이 필요한 코드를 찾는 도구이다.
