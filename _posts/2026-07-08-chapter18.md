## 18장: 테이블 기반 기법

### 18.1 테이블 기반 기법의 일반적인 고려사항

- 복잡한 논리나 반복되는 조건을 코드 대신 데이터 테이블에서 조회하는 방식임
- 조건문이 늘어날수록 테이블은 규칙을 한눈에 보여 주고 변경 지점을 줄일 수 있음
- 먼저 동작을 테이블에 넣을 수 있는지, 입력을 유효한 키로 바꿀 수 있는지 판단함
- 테이블에는 데이터뿐 아니라 함수, 객체, 상태 전이 같은 처리 동작도 저장할 수 있음
- 테이블을 사용해도 경계 검사, 잘못된 키 처리, 초기화 방법은 명시해야 함

### 18.2 직접 접근 테이블

- 입력값을 배열 인덱스나 맵 키로 직접 사용해 결과를 찾음
- 키 범위가 작고 조밀하면 배열이 단순하고 빠름
- 키가 희소하거나 문자열이면 해시 테이블이나 맵이 적합함
- 복잡한 키는 먼저 정규화하거나 별도의 키 생성 루틴으로 변환함
- 중복된 데이터가 많다면 테이블 크기와 코드 단순화 이익을 함께 비교함

#### 직접 접근 테이블에 넣을 수 있는 내용

- 월별 일수, 문자 분류, 상태별 동작처럼 고정된 값
- 조건 조합에 따른 결과
- 객체나 루틴 참조를 이용한 처리 선택
- 여러 속성을 가진 레코드

### 18.3 인덱스 접근 테이블

- 원본 키를 작은 인덱스로 변환한 뒤 실제 데이터 테이블에 접근함
- 데이터 레코드가 크거나 여러 테이블이 같은 키 순서를 공유할 때 공간을 절약함
- 인덱스 테이블을 정렬하면 이진 검색 같은 효율적인 탐색을 사용할 수 있음
- 키와 인덱스의 대응이 깨지지 않도록 생성과 검증을 한곳에서 관리함

### 18.4 계단식 접근 테이블

- 연속된 범위를 몇 개 구간으로 나누고 각 구간에 결과를 대응시킴
- 등급, 세율, 보험료처럼 값의 범위에 따라 결과가 달라지는 문제에 적합함
- 각 항목에 구간의 상한이나 하한을 저장하고 순서대로 비교함
- 경계값이 어느 구간에 속하는지 규칙을 일관되게 정함
- 마지막 구간과 범위 밖 입력을 명시적으로 처리함

### 18.5 테이블 조회의 다른 예

- 논리식을 진리표로 표현해 복잡한 boolean 조건을 단순화할 수 있음
- 상태와 입력 조합을 상태 전이 테이블로 표현할 수 있음
- 메시지 종류와 처리 루틴을 연결해 큰 분기문을 줄일 수 있음
- 생성되는 규칙이나 자주 바뀌는 정책은 코드와 분리된 테이블로 관리할 수 있음

### 요점 정리

- 테이블 기반 기법은 복잡한 논리를 데이터로 옮겨 코드와 변경을 단순하게 만든다.
- 키의 형태와 데이터 밀도에 따라 직접 접근, 인덱스 접근, 계단식 접근을 선택해야 한다.
- 테이블의 장점은 속도뿐 아니라 규칙을 한곳에서 보고 검증할 수 있다는 데 있다.
